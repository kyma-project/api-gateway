## Processing Status Limited to Downtime-Causing Changes

Previously, the `Processing` status was set on every reconciliation of the APIGateway CR. To reduce unnecessary status transitions, the `Processing` status is now only set when a change causes downtime — specifically, when `enableKymaGateway` is being disabled (which deletes the Istio Gateway resource).

Initial installation also triggers `Processing` as before. Other spec changes, such as toggling `networkPoliciesEnabled`, no longer trigger the `Processing` status. See [Proposal of handling of module status - #1630](https://github.com/kyma-project/api-gateway/pull/1630).
