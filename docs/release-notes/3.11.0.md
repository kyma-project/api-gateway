## Processing Status Limited to Spec Changes

Previously, the `Processing` status was set on every reconciliation of the APIGateway CR, including periodic re-syncs with no user-initiated changes. To reduce unnecessary status transitions, the `Processing` status is now only set when the CR generation advances — that is, when the spec actually changes — or on initial installation.

Periodic reconciliations that do not modify the spec no longer trigger the `Processing` status. See [Proposal of handling of module status - #1630](https://github.com/kyma-project/api-gateway/pull/1630).
