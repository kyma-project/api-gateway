## New Features

- The APIGateway CR status now includes granular per-subsystem conditions (`KymaGatewayReady`, `CertificateReady`, `DNSEntryReady`, `NetworkPolicyReady`, `DependenciesReady`) alongside the aggregate `Ready` condition, following Kubernetes API conventions. You can observe the readiness of individual subsystems without parsing `status.description` and use `kubectl wait` to wait for a specific subsystem to become ready. For example, `kubectl wait --for=condition=KymaGatewayReady apigateway/default`. See [PR #2902](https://github.com/kyma-project/api-gateway/pull/2902).
- The RateLimit CR status now includes structured conditions (`DependenciesReady`, `Ready`) following Kubernetes API conventions. You can observe the readiness of individual reconciliation steps without parsing `status.description` and use `kubectl wait` to wait for the CR to become ready. For example, `kubectl wait --for=condition=Ready ratelimit/my-ratelimit`. See [PR #2923](https://github.com/kyma-project/api-gateway/pull/2923).
