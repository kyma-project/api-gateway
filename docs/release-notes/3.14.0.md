## New Features

- The APIGateway CR status now includes granular per-subsystem conditions (`KymaGatewayReady`, `CertificateReady`, `DNSEntryReady`, `NetworkPolicyReady`, `DependenciesReady`) alongside the aggregate `Ready` condition, following Kubernetes API conventions. You can observe the readiness of individual subsystems without parsing `status.description` and use `kubectl wait` to wait for a specific subsystem to become ready. For example, `kubectl wait --for=condition=KymaGatewayReady apigateway/default`. See [PR #2902](https://github.com/kyma-project/api-gateway/pull/2902).
- The APIRule CR status now includes granular per-subsystem conditions (`VirtualServiceConfigured`, `RequestAuthenticationConfigured`, `AuthorizationPolicyConfigured`, `DependenciesReady`) alongside the aggregate `Ready` condition, following Kubernetes API conventions. You can observe the readiness of individual subsystems without parsing `status.description` and use `kubectl wait` to wait for a specific subsystem to become ready. For example, `kubectl wait --for=condition=Ready apirule/<name>`. See [PR #2913](https://github.com/kyma-project/api-gateway/pull/2913).
